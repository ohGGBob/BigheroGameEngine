## 二、P0：真 Bug（优先修，收益立竿见影）

### R1 · CSM 级联阴影瓦片尺寸错误 —— 阴影分辨率只有应得的 1/4

**位置**：`src/render/ShadowMap.h:36`、`src/render/ShadowMap.cpp`（`RecordPass`）、`src/app/Application.cpp:2148`

**问题**（C++ 与 GLSL 约定不一致）：

```cpp
// ShadowMap.h:36  与  ShadowMap.cpp RecordPass 内
static constexpr uint32_t kCascadeCount = 4;
uint32_t CascadeTileSize() const { return size_ / kCascadeCount; }  // 2048/4 = 512  ← 错
const uint32_t tile = size_ / kCascadeCount;                        // 同上，512
```

但 2×2 图集里，4 个级联的瓦片边长应为 `size_ / 2 = 1024`（每行/每列 2 块）。
着色器端正是按 0.5 采样的：

```glsl
// shaders/deferred_light.frag.glsl:130
const vec2 tileOffset = vec2(float(cascade & 1), float(cascade / 2)) * 0.5;  // ← 假设瓦片占半张图
```

**后果**：

1. 4 个级联只写入左上角 **1024×1024** 区域（每块 512×512），**75% 的 2048² 深度图集被浪费**；
2. 级联 1/2/3 按 0.5 偏移采样，大量采到未渲染区域（clear = 1.0，最远深度）→ 阴影错误/缺失；
3. 有效阴影分辨率 512² 而非 1024²（**损失 4 倍**），边缘锯齿明显；
4. `Application.cpp:2148` 的 `tileTexels`（texel-snap 防阴影闪烁）基于 512 计算 → 抖动量同样错误。

**方案**：

- 引入 `static constexpr uint32_t kAtlasDim = 2;`（2×2 图集），`CascadeTileSize()` 与 `RecordPass` 的 `tile`
  统一改为 `size_ / kAtlasDim`；`kCascadeCount` 仅表示级联数量，不再参与尺寸计算。
- 补纯逻辑单测（无需 GPU）：断言 `CascadeTileSize() == size_/2`、4 个级联 viewport 并集恰好铺满整图、
  与 GLSL 的 0.5 偏移一致。

**收益**：阴影分辨率 ×4、级联采样归位、texel-snap 正确、阴影闪烁减轻。

### P1 · 物理 Step 残差用可变步长 —— 破坏确定性

**位置**：`src/physics/PhysicsEngine.cpp:104-118`

```cpp
const float fixedStep = 1.0f / 60.0f;
float remaining = std::min(deltaTime, 0.1f);
while (remaining > fixedStep * 0.5f) { world_->update(fixedStep); remaining -= fixedStep; }
if (remaining > 0.0f) world_->update(remaining);   // ← 可变长尾步，步长不定
```

**问题**：同一次运行内步长忽长忽短 → 物理不确定（同输入不同结果）、碰撞求解稳定性下降
（rp3d 对步长变化敏感）、引擎的**录制回调无法复现**。

**方案**：标准累加器模式 —— 累加 `dt`，只以固定步长推进，余量留到下一帧，**不再跑可变步长尾步**：

```cpp
accumulator_ += std::min(deltaTime, 0.1f);
while (accumulator_ >= fixedStep) { SavePrevTransforms(); world_->update(fixedStep); accumulator_ -= fixedStep; }
alpha_ = accumulator_ / fixedStep;   // 供渲染插值
```

### P2 · 缺少渲染插值 → 高刷屏 / 低帧率抖动

**位置**：`PhysicsEngine::GetBodyTransform`（`PhysicsEngine.cpp:214`）

**问题**：物理 60 Hz 阶跃更新，渲染帧率任意 → 刚体位置每 1/60 s 跳一次。144 Hz 屏或帧率波动时肉眼可见抖动。

**方案**：每步物理前缓存 `prev` 变换，`GetBodyTransform(id, alpha)` 提供插值版本
（位置 lerp + 四元数 slerp），由场景同步层按 `alpha_` 取值；不需要插值的静态/运动学体直读当前值。

## 三、P1：性能与资源

| 编号 | 项目 | 位置 | 方案要点 | 收益 |
|---|---|---|---|---|
| T1 | **块压缩 BC / ASTC** | `Texture.cpp:130`（一律 RGBA8） | 加载期转码 BC1/BC3/BC5/BC7（桌面）/ ASTC（Android），运行时按 `vkGetPhysicalDeviceFormatProperties` 探测支持并回退未压缩 | 显存 ↓75%（32bpp → 8bpp）、带宽与 cache 命中改善 |
| T2 | **ORM 通道打包** | glTF 材质接入层 | metallicRoughness 实际仅用 G/B 两通道 → 与 AO 打包为单张 ORM；法线转 RG8/BC5 | 每材质 3 张 → 2 张 |
| R3 | **Sampler 复用缓存** | `Texture.cpp:93-111`（每张纹理建一个） | 按 (filter, address, aniso, mipLevels) 做全局缓存；避免 Vulkan sampler 数量与描述符写入膨胀 | 减少对象数与每帧描述符更新 |
| P3 | **空闲 ID 复用** | `PhysicsEngine::RemoveBody`（`PhysicsEngine.cpp:172`） | 目前删除仅置 `active_=false`，数组只增不减；改自由链表复用 ID | 长时间反复生成/销毁不再单调膨胀（右键生成物理立方体 demo 直接受益） |
| P4 | **Raycast 反查 O(1)** | `PhysicsEngine.cpp:339-350` | 命中后线性扫 `bodies_` 找 userTag → 改 `unordered_map<rp3d::Body*, uint32_t>` | 拾取/AI 射线从 O(n) 降到 O(1) |

## 四、P2：质量与手感打磨

| 编号 | 项目 | 说明 |
|---|---|---|
| R2 | **各向异性档位 + LOD bias** | 当前一律开到 `MaxSamplerAnisotropy()`（16x）。补纹理质量档（1x/4x/16x）+ 全局 mip LOD bias 滑杆，兼顾性能与远处清晰度 |
| R4 | **mip 链 sRGB 正确性** | `Image::GenerateMipmaps` 对 `R8G8B8A8_SRGB` 直接 `vkCmdBlitImage`，可能在编码空间插值导致 mip 偏暗；改用 UNORM 视图 blit 或自研 downsample，并用视觉对比确认 |
| T3 | **用途枚举自动选格式** | `CreateFromFile(ctx, path, sRGB)` 靠调用方手传 bool（法线贴图传 true 即光照错误）。改 `TextureUsage` 枚举（Albedo/Normal/MetallicRoughness/Occlusion/Emissive/Data）自动定格式 |
| T4 | **异步流式加载** | 复用已有 `ThreadPool.h`：工作线程解码 + 暂存，主线程只做 GPU 上传，消除大贴图卡顿 |
| P5 | **碰撞过滤 / 层掩码** | `world_->raycast(ray, &cb, 0xFFFF)` 全掩码；`BodyConfig` 加 category/mask，支持「只打敌人 / 忽略触发器」 |
| P6 | **形状与阻尼扩展** | 现仅 Sphere/Capsule/Box；补凸包 / Trimesh，并暴露 `setLinearDamping/setAngularDamping` 与睡眠阈值，便于角色手感调参 |
